1. 시작하기 전에

  • 주소: https://jkm-finance.github.io/csa/
  • 브라우저: 회사 PC의 Edge(또는 Chrome) 일반 창에서 여세요. InPrivate·시크릿 창은 창을 닫으면 데이터가 사라질 수 있어 쓰지 않습니다.
  • 비밀번호: 호텔 작업(작성자·리뷰어·Hotel DOF)은 jkm, Area / Regional DOF 취합은 apac. 비밀번호는 탭마다 한 번 입력합니다.
  • 이름: 시작 화면의 내 이름에 본인 이름을 입력합니다. 변경 이력에 이 이름이 남습니다. 작성자는 리뷰어가 배정에 쓴 이름과 똑같이 입력하세요(예: Irene Kim).
  • 언어: 화면 아래 또는 상단의 KO EN JA로 바꿉니다. 문항은 번역문으로 보이고, 영어 원문 보기를 누르면 원문이 펼쳐집니다. AuditBoard에는 영어 원문 기준으로 입력합니다.
데이터는 어디에 저장되나요? 입력한 내용은 내 PC의 브라우저 안에만 저장되고 인터넷 서버로 보내지 않습니다. 사람 사이의 전달은 모두 파일(메일·Teams·OneDrive로 주고받음)로 합니다. 그래서 자동 백업 폴더를 꼭 지정해 두세요.
호텔끼리 섞이지 않나요? 작업공간마다 고유 ID가 붙습니다. 이름이 같은 호텔이라도 서로 다른 작업공간이며, 다른 호텔·다른 연도·Full/Focus가 다른 파일은 불러올 때 자동으로 거부됩니다.

2. 전체 흐름 한눈에 보기

① 리뷰어: 새 CSA 시작→② 배정 파일 보내기→③ 작성자: 입력·섹션 제출→ ④ 리뷰어: 병합·검토→⑤ 검토 결과 회신(반려 수정)→⑥ AuditBoard 입력·잠금→ ⑦ 확정·최종 결과 파일→⑧ Hotel DOF 열람 · Area/Regional 취합
파일누가 만들고누구에게파일 이름 예
배정 파일리뷰어작성자CSA2026_Conrad_Seoul_Full_ASSIGN_v1_….json
제출 파일작성자리뷰어…_SUBMIT_AP_Irene_Kim_….json
검토 결과 파일리뷰어작성자…_REVIEW_….json
최종 결과 파일리뷰어Hotel DOF, Area / Regional DOF…_FINAL_v1_….json
전체 백업 파일본인본인(PC 교체 시)…_BACKUP_….json, …_LATEST.json

파일은 열어서 고치지 마세요. 파일마다 검증값이 들어 있어서 내용이 한 글자라도 바뀌면 불러올 때 거부됩니다.

리뷰어 혼자 모든 문항을 입력해도 됩니다. 이때는 ②~⑤를 건너뛰고 리뷰어 화면에서 바로 입력·승인한 뒤 ⑥~⑧로 갑니다.

3. 리뷰어(Manager)

3-1. 작업공간 만들기

  1. 비밀번호 jkm → 내 이름 입력 → 새 CSA 시작 (리뷰어).
  2. 호텔명을 입력하고 서비스 유형 Full(240문항) 또는 Focus(145문항)를 고른 뒤 만들기.
  3. 또는 AuditBoard 내보내기 엑셀로 시작 (리뷰어): AuditBoard에서 내려받은 감사 엑셀(.xlsx)을 넣으면 Full/Focus와 호텔명이 자동으로 채워지고, 문항마다 AuditBoard ID가 연결됩니다. 만들기 전에 맞춘 문항 수와 맞지 않는 행을 보여 줍니다. 이미 만든 작업공간에는 「배정」 탭의 AuditBoard ID 연결로 ID만 붙일 수 있습니다(입력 내용은 바뀌지 않음).
  4. 상단에 노란 안내가 보이면 백업 폴더 지정을 눌러 OneDrive 안의 폴더(예: OneDrive › Finance › CSA 2026 Backup)를 고릅니다. 7장 참고.

3-2. 섹션 배정과 배정 파일

일정: 「배정」 탭 일정에 단계별 마감일(CSA 배부 → 항목 작성 → 증빙 자료 제출 → 1차 검토 → Manager 인터뷰 → DOF·ADOF 검토 → AuditBoard 최종 제출)을 넣으면, 마감 7일 전부터 모든 사람 화면 위에 다음 일정 (D-3)처럼 안내가 뜨고 지나면 경고로 바뀝니다. 끝난 단계는 완료일을 넣으세요. 개요에는 일정 표와 날짜별 진행(하루 한 줄 자동 집계)이 보입니다.
전년도 결과: 「배정」 탭 전년도 결과 불러오기에 작년 결과 엑셀(Work Step·Response·Testing Notes 열, 또는 "2025 CSA | 2026 CSA" 비교 시트)을 넣으면 문항마다 2025: No 배지와 당시 테스트 노트가 보이고, 2025년 No 필터로 작년 지적 문항만 모아 볼 수 있습니다. 연도 표시가 없는 시트는 올해 결과일 수 있어 처음엔 선택되지 않으니, 시트 목록을 확인하고 적용하세요. 배정 파일에 함께 들어가 작성자도 봅니다.
  1. 배정 탭에서 섹션마다 담당자 이름을 입력합니다. 여러 명은 쉼표로 구분합니다(예: Irene Kim, Brad Jeong). FSSC가 없는 호텔은 FSSC 표시 문항도 호텔 직원에게 배정하면 됩니다.
  2. 배정 저장.
  3. 섹션 안에서 일부 문항만 다른 사람이 맡으면 문항별 담당자를 씁니다. 문항 화면 위쪽의 담당자 칸을 눌러 이름을 넣거나, 「배정」 탭 문항별 담당자에 엑셀의 # 열과 담당자(PIC) 열을 함께 복사해 붙여넣고 미리 보기 → 적용을 누릅니다. AR_HaEun은 HaEun으로 바뀌고, 담당자가 없던 섹션은 가장 많이 나온 사람이 섹션 담당자가 됩니다. 작성자는 자기 문항만 고치고 제출할 수 있습니다.
  4. 배정 파일 보내기에서 공통 배정 파일 내려받기(모두에게 같은 파일) 또는 {이름}용을 눌러 파일을 받은 뒤, 메일·Teams·OneDrive로 작성자에게 보냅니다.
  5. 배정을 바꾸면 버전이 올라갑니다. 새 배정 파일을 다시 보내면 작성자가 입력한 내용은 그대로 두고 배정만 바뀝니다.

3-3. 제출 파일 병합

  1. 병합·확정 탭 → 제출 파일 병합 상자에 받은 제출 파일을 한꺼번에 끌어다 놓습니다.
  2. 병합 미리보기에서 파일별로 신규·변경·동일·충돌·거부(잠금)·배정 외 건수를 확인합니다. 다른 호텔의 파일이나 손상된 파일은 그 파일만 거부되고 나머지는 처리됩니다.
  3. 충돌(두 사람이 같은 문항을 다르게 썼거나, 내가 고친 뒤에 들어온 제출)이 있으면 충돌 해결로 → 문항마다 쓸 내용을 고릅니다. 모두 지금 내용을 유지하려면 모두 정본 유지. 채택하지 않은 내용도 이력에 남습니다.
  4. 배정 외 문항은 체크한 것만 반영됩니다.
  5. 적용. 적용 직전에 복원 지점이 자동으로 만들어집니다.

3-4. 검토 — 승인과 반려

  • 작성자는 작성자 설명 (국문 · 내부용)을 쓰고, 리뷰어는 이를 바탕으로 AuditBoard Response (영문 · 리뷰어 확정)을 작성·확정합니다. 왼쪽 필터의 AuditBoard Response 없음으로 아직 영문 Response가 없는 문항만 모아 볼 수 있습니다.
  • 검토함 탭에 제출된 문항이 모입니다. 문항을 열어 내용을 보고 승인 또는 반려를 누릅니다. 반려는 사유를 꼭 입력해야 합니다.
  • 여러 건은 결과가 있는 n건 일괄 승인으로 한 번에 승인할 수 있습니다.
  • 문항 아래 리뷰 코멘트에 의견을 남길 수 있습니다(추가만 가능, 지울 수 없음).
  • 검토완료 문항의 결과를 바꾸면 사유를 꼭 입력해야 합니다. 사유는 코멘트(작성자에게도 보임)와 변경 이력에 남고, 개요의 검토완료 후 결과 변경 표에 모입니다.
  • 리뷰어는 검토완료 문항도 직접 고칠 수 있습니다. 상태는 검토완료 그대로이며, 이미 확정한 뒤라면 확정이 해제됩니다. 입력완료(잠김) 문항은 먼저 잠금을 해제해야 합니다.

3-5. 검토 결과 보내기

병합·확정 탭 → 검토 결과 파일 내려받기 → 작성자에게 보냅니다. 승인·반려 상태와 코멘트가 전달되며, 작성자가 그사이 고친 내용은 덮어쓰지 않습니다.

3-6. AuditBoard 입력과 잠금

  1. AuditBoard ID가 연결되어 있으면 문항 머리에 AB 1283309처럼 보이고, 목록 위 찾기 칸에 AuditBoard ID나 # 번호를 넣으면 그 문항으로 바로 갈 수 있습니다.
  2. 승인된 문항을 Hilton AuditBoard에 입력합니다. 문항 화면의 AuditBoard용 복사를 누르면 결과·AuditBoard Response·증빙 위치가 클립보드에 복사됩니다(작성자 설명은 복사되지 않음, Response가 비어 있으면 경고)(복사 형식은 AuditBoard 화면 확인 후 조정 예정).
  3. 입력이 끝난 문항은 AuditBoard 입력 완료를 누릅니다. 문항이 잠겨 누구도 고칠 수 없고, 이후 들어오는 제출도 거부됩니다.
  4. 잘못 잠갔거나 고쳐야 하면 잠금 해제(사유 필수). 해제 직전에 복원 지점이 만들어집니다.

3-7. 확정과 최종 결과 파일

  1. 모든 문항에 결과가 있고 검토완료(또는 입력완료)이면 병합·확정 탭의 확정하고 최종 결과 파일 발행이 켜집니다. 꺼져 있으면 아래 목록에 남은 문항이 표시됩니다.
  2. 발행된 …_FINAL_v1_….json 파일을 Hotel DOF와 Area / Regional DOF에게 보냅니다.
  3. 확정 뒤에 내용을 고치면 확정이 자동으로 해제됩니다(상단 안내 표시). 다시 확정하면 v2가 발행되고, 받는 쪽에서는 가장 높은 버전이 기본으로 보입니다. AuditBoard 입력 완료 표시나 잠금 해제만으로는 확정이 풀리지 않습니다.

3-8. 보고서와 Excel

  • DOF 보고 탭: 점수·섹션별 결과·Findings와 개선계획·Hold 목록. 인쇄 / PDF 저장 → 인쇄 창에서 “PDF로 저장”(A4 세로). 확정 전에는 “초안 — 미확정” 표시가 붙습니다.
  • 병합·확정 탭의 전체 Excel 내보내기: 문항별 결과·내용·담당자·최근 코멘트 전체.
  • Overview: 진행률(Yes+No+N/A ÷ 전체), 점수(Yes ÷ (Yes+No), N/A·Hold 제외), 섹션별·담당자별·상태별 현황.

4. 작성자

4-1. 처음 시작

  1. 리뷰어에게 받은 배정 파일(…_ASSIGN_….json)을 PC에 저장합니다.
  2. 주소를 열고 비밀번호 jkm → 내 이름을 배정에 적힌 이름 그대로 입력.
  3. 배정 파일 불러오기 (작성자) → 파일 선택. 이름이 목록에 없으면 목록에서 내 이름을 고르는 창이 뜹니다.
  4. 다음부터는 시작 화면의 내 작업공간에서 호텔을 눌러 이어서 작업합니다.

4-2. 문항 입력

  • 상단 섹션 탭에서 ● 표시된 섹션(내 문항이 있는 섹션)을 열고, 왼쪽 목록에서 문항을 고릅니다. 흐리게 보이는 문항은 다른 사람 담당이라 고칠 수 없고 제출 파일에도 들어가지 않습니다. 필터(위험 등급·상태·미응답만 등)로 좁힐 수 있습니다.
  • 결과: Yes(통제가 잘 운영됨) · No(미흡) · N/A(해당 없음) · Hold(판정 보류 — 확인 중).
  • 작성자 설명 (국문 · 내부용): 담당자, 현재 수행 중인 프로세스, 증빙을 국문으로 적습니다. AuditBoard에는 들어가지 않습니다.
  • AuditBoard Response (영문 · 리뷰어 확정): AuditBoard에 그대로 입력할 영문 문장입니다. 작성자가 초안을 써도 되지만, 리뷰어가 작성자 설명을 보고 확정합니다.
  • 증빙 자료 위치: 파일 경로나 보관 위치. L:\… 같은 경로나 웹 링크를 한 줄에 하나씩 적으면 아래에 경로 복사 버튼이 생깁니다. 웹 페이지는 보안상 폴더를 직접 열 수 없으니, 복사해서 파일 탐색기 주소창(Ctrl+L)에 붙여넣으세요. 샘플 테스트 내역: 확인한 샘플(기간·건수 등). 각 5,000자까지.
  • 문항 위에 2025: No처럼 작년 결과가 보이면 당시 테스트 노트를 참고해 올해 개선되었는지 적어 주세요.
  • 결과가 No이면 개선계획(조치 내용·담당자·완료 예정일)을 꼭 입력합니다.
  • 입력은 자동 저장됩니다(상단 오른쪽에 저장 시각 표시). 따로 저장 버튼은 없습니다.
  • 회색으로 꺼진 버튼이나 입력란에 마우스를 올리면 이유가 나옵니다(예: “잠긴 문항입니다”, “내 담당 문항이 아닙니다”).

4-3. 섹션 제출

  1. 제출·받기 탭 → 섹션 제출에서 제출할 섹션을 체크합니다(● = 내 담당).
  2. 제출 파일 내려받기. 결과가 없는 문항은 빠지고, No인데 개선계획이 없거나 내 담당이 아닌 섹션이 있으면 경고가 나옵니다.
  3. 내려받은 …_SUBMIT_….json 파일을 리뷰어에게 보내야 제출이 끝납니다.
  4. 섹션을 나눠서 여러 번 제출해도 됩니다. 이미 제출한 문항을 고친 뒤 다시 제출해도 됩니다.

4-4. 검토 결과 받기와 반려 수정

  1. 리뷰어가 보낸 검토 결과 파일(…_REVIEW_….json) 또는 새 배정 파일을 제출·받기 탭 → 리뷰어 파일 받기에 넣습니다.
  2. 반려 탭에 반려된 문항과 사유가 보입니다. 고친 뒤 다시 제출합니다.
  3. 아직 보내지 않은 내 입력은 덮어쓰지 않습니다. 이런 문항에는 “리뷰어 정본과 내용이 다릅니다” 표시가 붙으니, 수정이 끝나면 다시 제출하세요.
  4. 검토완료된 문항은 작성자가 고칠 수 없습니다. 고쳐야 하면 리뷰어에게 반려를 요청하세요.
작성자도 백업·복원 탭에서 백업 폴더 지정을 해 두면 PC 문제에 대비할 수 있습니다.

5. Hotel DOF

  1. 리뷰어에게 최종 결과 파일(…_FINAL_v1_….json)을 받습니다.
  2. 비밀번호 jkm → 최종 결과 파일 열기 (Hotel DOF) → 파일 선택.
  3. 보고서 탭: 점수·섹션별 결과·Findings와 개선계획·Hold. 문항 상세 탭: 문항별 결과와 Response(읽기 전용).
  4. 인쇄 / PDF 저장 → “PDF로 저장”으로 보고용 PDF(A4)를 만듭니다. 영어 원문 함께 표시를 켜면 번역문 아래 원문도 인쇄됩니다.
  5. 한 번 연 결과는 이 브라우저에 남습니다. 다음에는 시작 화면의 열람한 최종 결과 다시 보기로 엽니다. v2가 오면 같은 방법으로 열고, 상단 목록에서 이전 버전도 고를 수 있습니다.

이 화면에서는 아무것도 고칠 수 없습니다. 수정이 필요하면 리뷰어에게 요청하세요.

6. Area / Regional DOF

  1. 각 호텔 리뷰어에게 최종 결과 파일을 받습니다.
  2. 비밀번호 apac로 들어갑니다(취합 모드).
  3. 최종 결과 파일 불러오기 상자에 여러 호텔의 파일을 한꺼번에 끌어다 놓습니다. 같은 호텔은 가장 높은 버전만 집계하고, 이전 버전은 이력으로 남습니다.
  4. 호텔별: 호텔마다 점수·Key/HR/MR·No·Hold·AuditBoard 입력률. 호텔명을 누르면 그 호텔의 DOF 보고서가 열립니다.
  5. 섹션 히트맵: 호텔×섹션 점수(Full·Focus 혼합 시 Focus에 없는 섹션은 빈칸).
  6. 전체 Findings: 모든 호텔의 No 문항과 개선계획. 완료 예정일이 지난 것은 ⚠로 강조됩니다.
  7. 취합 Excel 내보내기: 호텔 요약·히트맵·Findings 3개 시트.

같은 버전 번호인데 내용이 다른 파일이 들어오면 ⚠ 경고가 붙습니다. 해당 호텔 리뷰어에게 확인하세요. 목록에서 제거는 이 취합 화면에서만 빼는 것이며 호텔 데이터에는 영향이 없습니다.

PC를 바꿀 때 / 리뷰어가 바뀔 때

  1. 기존 PC에서 전체 백업 내려받기(또는 백업 폴더의 …_LATEST.json 사용).
  2. 새 PC에서 비밀번호 → 이름 → 전체 백업 파일로 복원 → 파일 선택. 같은 작업공간(같은 ID)으로 복원되어 기존 작성자의 제출 파일도 그대로 병합할 수 있습니다.

작업공간 숨기기 · 삭제

  • 목록에서 숨기기 (데이터 유지): 시작 화면 목록에서만 숨깁니다. 언제든 다시 표시할 수 있습니다.
  • 작업공간 완전 삭제: ① 전체 백업을 먼저 내려받고 ② 호텔명을 정확히 입력해야만 삭제됩니다. 이 PC의 복원 지점까지 지워지므로 내려받은 백업 파일이 유일한 복구 수단입니다.
브라우저의 “인터넷 사용 기록 삭제(쿠키 및 사이트 데이터)”를 하면 이 PC의 작업 데이터가 지워집니다. 자동 백업 폴더를 지정해 두었다면 전체 백업 파일로 복원으로 되살릴 수 있습니다.
빨간 안내 “예상하지 못한 오류가 발생해 자동 저장을 멈췄습니다”가 보이면 그 안의 전체 백업 내려받기를 먼저 누른 뒤 새로고침하세요. 잘못된 상태가 저장되지 않도록 일부러 멈춘 것입니다.
