1. はじめに

  • アドレス: https://jkm-finance.github.io/csa/
  • ブラウザ: 会社PCのEdge（またはChrome）の通常ウィンドウで開いてください。InPrivate/シークレットウィンドウは閉じるとデータが消える恐れがあるため使用しません。
  • パスワード: ホテル作業（作成者・レビュアー・Hotel DOF）は jkm、Area / Regional DOF の集計は apac。タブごとに1回入力します。
  • 氏名: 最初の画面の お名前 に入力します。変更履歴にこの名前が残ります。作成者は、レビュアーが割当に書いた名前とまったく同じに入力してください（例: Irene Kim）。
  • 言語: KO EN JA で切り替えます。項目は翻訳文で表示され、英語原文を表示 で原文を確認できます。AuditBoardへは英語原文に基づいて入力します。
データはどこに保存されますか？ 入力内容は自分のPCのブラウザ内だけに保存され、サーバーには送られません。人と人のやり取りはすべてファイル（メール・Teams・OneDrive）で行います。そのため自動バックアップ先を必ず指定してください。
ホテル同士のデータが混ざりませんか？ ワークスペースごとに固有IDが付きます。同じ名前のホテルでも別のワークスペースとして扱われ、他ホテル・他年度・Full/Focusが異なるファイルは読み込み時に自動で拒否されます。

2. 全体の流れ

① レビュアー: 新規CSA→② 割当ファイルを送る→③ 作成者: 入力・セクション提出→ ④ レビュアー: マージ・レビュー→⑤ レビュー結果を返す（差戻し修正）→⑥ AuditBoard入力・ロック→ ⑦ 確定・最終結果ファイル→⑧ Hotel DOF閲覧・Area/Regional集計
ファイル作成者送付先ファイル名の例
割当ファイルレビュアー作成者CSA2026_Hilton_Fukuoka_Sea_Hawk_Focus_ASSIGN_v1_….json
提出ファイル作成者レビュアー…_SUBMIT_AP_Irene_Kim_….json
レビュー結果ファイルレビュアー作成者…_REVIEW_….json
最終結果ファイルレビュアーHotel DOF、Area / Regional DOF…_FINAL_v1_….json
フルバックアップ本人本人（PC変更時）…_BACKUP_….json、…_LATEST.json

ファイルを開いて編集しないでください。各ファイルには検証値が入っており、1文字でも変わると読み込み時に拒否されます。

レビュアーが一人で全項目を入力することもできます。その場合は②〜⑤を省き、レビュアー画面で直接入力・承認してから⑥〜⑧に進みます。

3. レビュアー（Manager）

3-1. ワークスペースの作成

  1. パスワード jkm → お名前 を入力 → 新規CSA（レビュアー）。
  2. ホテル名を入力し、サービス区分 Full（240項目）または Focus（145項目）を選んで 作成。
  3. または AuditBoardエクスポートから開始（レビュアー）: AuditBoardからダウンロードした監査Excel（.xlsx）を入れると、Full/Focusとホテル名が自動入力され、各項目にAuditBoard IDが紐付きます。作成前に一致した項目数と一致しない行が表示されます。既存のワークスペースには「割当」タブの AuditBoard IDを紐付け でIDのみ追加できます（入力内容は変わりません）。
  4. 上部に黄色の案内が出たら バックアップ先を指定 を押し、OneDrive内のフォルダ（例: OneDrive › Finance › CSA 2026 Backup）を選びます。7章参照。

3-2. セクション割当と割当ファイル

スケジュール: 「割当」タブの スケジュール に段階別の締切日（CSA配布 → 項目作成 → 証憑提出 → 一次レビュー → Managerインタビュー → DOF・ADOFレビュー → AuditBoard最終提出）を入れると、締切7日前から全員の画面上部に 次の予定（D-3） のような案内が表示され、過ぎると警告になります。完了した段階は完了日を入れてください。概要にはスケジュール表と 日付別の進捗（1日1行自動集計）が表示されます。
前年度結果: 「割当」タブの 前年度結果を読み込む に昨年の結果Excel（Work Step・Response・Testing Notes列、または「2025 CSA | 2026 CSA」比較シート）を入れると、各項目に 2025: No バッジと当時のテストノートが表示され、2025年 No フィルターで昨年の指摘項目を絞り込めます。年度表示のないシートは今年の結果の可能性があるため最初は未選択です。シート一覧を確認してから適用してください。割当ファイルに含まれ、作成者も確認できます。
  1. 割当 タブでセクションごとに担当者名を入力します（複数はカンマ区切り、例: Irene Kim, Brad Jeong）。FSSCのないホテルは、FSSC表示の項目もホテルの担当者に割り当てます。
  2. 割当を保存。
  3. セクション内の一部の項目だけ別の人が担当する場合は項目別担当者を使います。項目画面上部の 担当者 欄を押して名前を入れるか、「割当」タブの 項目別担当者 にExcelの # 列と担当者（PIC）列を一緒にコピーして貼り付け、プレビュー → 適用 を押します。AR_HaEun は HaEun になり、担当者のいないセクションは最も多い人がセクション担当者になります。作成者は自分の項目のみ修正・提出できます。
  4. 割当ファイルを送る で 割当ファイルをダウンロード（全員共通）または {名前}用 を押してファイルを取得し、メール・Teams・OneDriveで作成者に送ります。
  5. 割当を変更するとバージョンが上がります。新しい割当ファイルを送っても、作成者の入力内容はそのままで割当だけが更新されます。

3-3. 提出ファイルのマージ

  1. マージ・確定 タブ → 提出ファイルのマージ に受け取った提出ファイルをまとめてドロップします。
  2. マージのプレビュー でファイルごとに 新規・変更・同一・競合・拒否（ロック）・割当外 の件数を確認します。他ホテルのファイルや破損したファイルはそのファイルだけ拒否され、残りは処理されます。
  3. 競合（2人が同じ項目を違う内容で回答、またはレビュアーが修正した後に届いた提出）がある場合は 競合の解決へ → 項目ごとに採用する内容を選びます。すべて現在の内容を残すなら すべて現行内容を維持。採用しなかった内容も履歴に残ります。
  4. 割当外の項目はチェックしたものだけ反映されます。
  5. 適用。適用直前に復元ポイントが自動作成されます。

3-4. レビュー — 承認と差戻し

  • 作成者は 作成者説明（社内用） を書き、レビュアーはそれをもとに AuditBoard Response（英語・レビュアー確定） を作成・確定します。フィルターの AuditBoard Responseなし で英文Responseが未作成の項目だけを表示できます。
  • レビュー待ち タブに提出された項目が集まります。項目を開いて 承認 または 差戻し を押します。差戻しには理由の入力が必要です。
  • 結果のあるn件を一括承認 でまとめて承認できます。
  • 項目下の レビューコメント に意見を残せます（追加のみ、削除不可）。
  • レビュー完了項目の結果を変更する場合は理由の入力が必要です。理由はコメント（作成者にも表示）と変更履歴に残り、概要の レビュー完了後の結果変更 表にまとまります。
  • レビュアーはレビュー完了の項目も直接修正できます。ステータスはレビュー完了のままで、確定後であれば確定が解除されます。入力完了（ロック）の項目は先にロックを解除します。

3-5. レビュー結果を送る

マージ・確定 タブ → レビュー結果ファイルをダウンロード → 作成者に送ります。承認・差戻しとコメントが伝わり、作成者がその間に修正した内容は上書きされません。

3-6. AuditBoard入力とロック

  1. AuditBoard IDが紐付いていると項目の上部に AB 1283309 のように表示され、一覧上の検索欄にAuditBoard IDや#番号を入れるとその項目へ移動できます。
  2. 承認済みの項目をHilton AuditBoardに入力します。項目画面の AuditBoard用にコピー で結果・AuditBoard Response・証憑の保管場所がクリップボードにコピーされます（作成者説明はコピーされません。Responseが空なら警告）（形式はAuditBoard画面の確認後に調整予定）。
  3. 入力が終わった項目は AuditBoard入力完了 を押します。項目がロックされ誰も修正できず、以後の提出も拒否されます。
  4. 修正が必要な場合は ロック解除（理由必須）。解除直前に復元ポイントが作成されます。

3-7. 確定と最終結果ファイル

  1. 全項目に結果があり、レビュー完了（または入力完了）になると、マージ・確定 タブの 確定して最終結果を発行 が押せるようになります。押せない場合は残りの項目が下に表示されます。
  2. 発行された …_FINAL_v1_….json をHotel DOFとArea / Regional DOFに送ります。
  3. 確定後に内容を修正すると確定は自動で解除されます（上部に案内表示）。再確定すると v2 が発行され、受け取った側では最新版が標準で表示されます。入力完了の表示やロック解除だけでは確定は解除されません。

3-8. レポートとExcel

  • DOFレポート タブ: スコア・セクション別結果・Findingsと改善計画・Hold一覧。印刷 / PDF保存 → 印刷画面で「PDFに保存」（A4縦）。確定前は「ドラフト — 未確定」と表示されます。
  • マージ・確定 タブの 全体をExcel出力: 項目ごとの結果・内容・担当者・最新コメント。
  • Overview: 進捗（(Yes+No+N/A) ÷ 全体）、スコア（Yes ÷ (Yes+No)、N/A・Hold除外）、セクション別・担当者別・ステータス別の状況。

4. 作成者

4-1. 最初の開始

  1. レビュアーから受け取った割当ファイル（…_ASSIGN_….json）をPCに保存します。
  2. アドレスを開き、パスワード jkm → お名前 を割当に書かれた名前のとおりに入力。
  3. 割当ファイルを開く（作成者） → ファイルを選択。名前がリストにない場合は、リストから自分の名前を選ぶ画面が出ます。
  4. 次回からは最初の画面の マイワークスペース でホテルを押して続けます。

4-2. 項目の入力

  • 上部のセクションタブから ● の付いたセクション（自分の項目があるセクション）を開き、左の一覧で項目を選びます。薄く表示される項目は他の人の担当のため修正できず、提出ファイルにも含まれません。フィルター（リスク・ステータス・未回答のみ など）で絞り込めます。
  • 結果: Yes（統制が運用されている）· No（不備）· N/A（該当なし）· Hold（判定保留 — 確認中）。
  • 作成者説明（社内用）: 担当者・現在のプロセス・証憑を記入します。AuditBoardには入力しません。
  • AuditBoard Response（英語・レビュアー確定）: AuditBoardにそのまま入力する英文です。作成者が下書きしてもよく、レビュアーが作成者説明をもとに確定します。
  • 証憑の保管場所: ファイルのパスや保管場所。L:\… などのパスやWebリンクを1行に1つずつ書くと、下に パスをコピー ボタンが表示されます。Webページはフォルダを直接開けないため、コピーしてエクスプローラーのアドレス欄（Ctrl+L）に貼り付けてください。サンプルテスト内容: 確認したサンプル（期間・件数など）。各5,000文字まで。
  • 項目の上に 2025: No のように昨年の結果が表示されたら、当時のテストノートを参考に今年改善された点を記入してください。
  • 結果が No の場合は必ず 改善計画（対応内容・担当者・完了予定日）を入力します。
  • 入力は自動保存されます（右上に保存時刻を表示）。保存ボタンはありません。
  • グレーで押せないボタンや入力欄にマウスを置くと理由が表示されます（例:「ロックされた項目です」「担当項目ではありません」）。

4-3. セクション提出

  1. 提出・受取 タブ → セクション提出 で提出するセクションにチェックします（● = 担当）。
  2. 提出ファイルをダウンロード。結果のない項目は含まれず、Noで改善計画がない項目や担当外のセクションがあれば警告が出ます。
  3. ダウンロードした …_SUBMIT_….json をレビュアーに送って提出完了です。
  4. セクションを分けて何回提出してもかまいません。提出済みの項目を修正して再提出することもできます。

4-4. レビュー結果の受け取りと差戻しの修正

  1. レビュアーから届いたレビュー結果ファイル（…_REVIEW_….json）または新しい割当ファイルを、提出・受取 タブの レビュアーのファイルを受け取る に入れます。
  2. 差戻し タブに差し戻された項目と理由が表示されます。修正して再提出します。
  3. まだ送っていない自分の入力は上書きされません。その項目には「レビュアーの内容と異なります」と表示されるので、修正が終わったら再提出してください。
  4. レビュー完了の項目は作成者は修正できません。修正が必要ならレビュアーに差戻しを依頼してください。
作成者も バックアップ タブで バックアップ先を指定 しておくと、PCの故障に備えられます。

5. Hotel DOF

  1. レビュアーから最終結果ファイル（…_FINAL_v1_….json）を受け取ります。
  2. パスワード jkm → 最終結果を開く（Hotel DOF） → ファイルを選択。
  3. レポート タブ: スコア・セクション別結果・Findingsと改善計画・Hold。項目詳細 タブ: 項目ごとの結果とResponse（閲覧のみ）。
  4. 印刷 / PDF保存 →「PDFに保存」で報告用PDF（A4）を作成します。英語原文も表示 をオンにすると翻訳文の下に原文も印刷されます。
  5. 一度開いた結果はこのブラウザに残ります。次回は最初の画面の 閲覧した最終結果を再表示 で開きます。v2が届いたら同じ方法で開き、上部の一覧から旧版も選べます。

この画面では何も変更できません。修正が必要な場合はレビュアーに依頼してください。

6. Area / Regional DOF

  1. 各ホテルのレビュアーから最終結果ファイルを受け取ります。
  2. パスワード apac で入ります（集計モード）。
  3. 最終結果ファイルの読み込み に複数ホテルのファイルをまとめてドロップします。同じホテルは最新版のみ集計し、旧版は履歴として残ります。
  4. ホテル別: ホテルごとのスコア・Key/HR/MR・No・Hold・AuditBoard入力率。ホテル名を押すとそのホテルのDOFレポートが開きます。
  5. セクション・ヒートマップ: ホテル×セクションのスコア（Full・Focus混在時、Focusにないセクションは空欄）。
  6. 全Findings: 全ホテルのNo項目と改善計画。完了予定日を過ぎたものは⚠で強調されます。
  7. 集計をExcel出力: ホテル概要・ヒートマップ・Findingsの3シート。

同じバージョン番号で内容の異なるファイルが届くと⚠が付きます。該当ホテルのレビュアーに確認してください。一覧から削除 はこの集計画面から外すだけで、ホテルのデータには影響しません。

7. データの安全 — バックアップと復元

仕組み内容場所
自動保存入力するたびにブラウザに保存し、保存直後に読み直して確認。直前の保存データも保管。自動
自動フォルダバックアップ15秒ごとに変更を確認し、指定フォルダに _LATEST.json と日付別ファイルを保存（30日保管）。他のファイルには触れません。バックアップ → バックアップ先を指定
復元ポイント変更があると5分ごと、またマージ・復元・ロック解除の直前に自動作成（30日保管）。バックアップ → この時点に復元
フルバックアップワークスペース全体（履歴・コメント含む）を1ファイルに。バックアップ → フルバックアップをダウンロード
急減の防止一度に多くの入力が消えると保存を停止して確認を求めます。元に戻す（最後の保存を維持） または 意図した削除です — 保存。自動
同時編集の防止同じワークスペースを2つ目のタブで開くと、そのタブは閲覧のみ。最初のタブを閉じたら 編集モードに切替。自動

PCを変えるとき / レビュアーが交代するとき

  1. 元のPCで フルバックアップをダウンロード（またはバックアップ先の …_LATEST.json を使用）。
  2. 新しいPCでパスワード → 氏名 → フルバックアップから復元 → ファイルを選択。同じワークスペース（同じID）として復元され、既存の作成者の提出ファイルもそのままマージできます。

ワークスペースの非表示・削除

  • 一覧から非表示（データは保持）: 最初の画面の一覧から隠すだけです。いつでも再表示できます。
  • ワークスペースを完全削除: ①先にフルバックアップをダウンロードし、②ホテル名を正確に入力した場合のみ削除されます。このPCの復元ポイントも消えるため、ダウンロードしたバックアップが唯一の復旧手段です。
ブラウザの「閲覧データの削除（Cookieとサイトデータ）」を行うと、このPCの作業データが消えます。バックアップ先を指定していれば フルバックアップから復元 で戻せます。
赤い案内「予期しないエラーのため自動保存を停止しました」が出たら、まずその中の フルバックアップをダウンロード を押してから再読み込みしてください。不正な状態が保存されないよう意図的に停止しています。

8. よくある質問・エラーメッセージ
